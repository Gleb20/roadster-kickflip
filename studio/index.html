Music preparation · Suno and export rules

Use a full loop, or four synchronized parts: bed, lead, bass and drums. Every biome needs music. Keep HUD and controls independent of the biome.

Tempo / meter
128 BPM · 4/4
Prepared loop
32 bars · exactly 60.000 seconds · start on the downbeat
Working export
WAV, stereo, 48 kHz preferred. Keep originals and source credits.
Game upload
MP3, stereo, 192–256 kbps recommended. Decode to check exactly 60 seconds. The game resamples to its audio context.
Stems
Same start, end, tempo and phase. Do not trim or normalize each part independently.
Transition
One-bar crossfade on the shared beat grid. Check compatible keys/harmony, balanced loudness and an audible bed without a vocal pickup.

Equal bitrate or sample rate does not make tracks seamless. Suno may drift from the requested tempo: measure, align and trim the export before uploading. Listen to both transition directions and to the seam. A duration check cannot certify tempo, phase or harmony.

This is a generation brief, not a guarantee of a sample-accurate loop. Prepare the generated recording in an audio editor, keep provenance, then upload and audition.

Compatibility and release

The studio exports a candidate; it does not write into the live game. A release builds the game and studio together from one validated package and resource hashes. Draft weights, dimensions, collision, reactions or biome pools require a frozen server ruleset before they can enter ranked play. Cosmetic edits retain the ruleset only if its gameplay digest still matches.

Images use fixed pixel layouts so atlas cells, anchors and hitboxes retain their meaning. Keep transparent padding and cell positions. New scene choreography or a new renderer profile requires code support; a JSON file cannot introduce arbitrary JavaScript.

Import is atomic: an incompatible or incomplete file leaves your current draft in place. Reload can restore your browser draft. Export before clearing browser data or moving to another Mac.
