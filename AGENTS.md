# Tesla Jump

## Обязательный пайплайн визуальных ассетов

При каждой просьбе нарисовать, сгенерировать или визуально переработать иллюстрацию/спрайт **для Tesla Jump** сначала прочитать и выполнить проектный skill [tesla-jump-art](.agents/skills/tesla-jump-art/SKILL.md), даже без явного упоминания навыка. Обязательный маршрут: реальный объект → проверенная фотография в нужном ракурсе → передача фото и игрового стилевого аналога в генерацию → прозрачный спрайт → визуальная проверка и фиксация происхождения. Для абстрактного класса сначала выбрать и назвать типичного реального представителя. Явный стиль пользователя приоритетен; иначе наследовать стиль актуальной категории/подкатегории, отдельно для препятствий, фона и деталей героя. Не заменять фото текстовым описанием и не распространять один стиль на всю игру. Обсуждение пайплайна само по себе не запускает рисование или переделку существующих ассетов.

Перед работой прочитать `docs/HANDOFF.md`, `RESTORATION.md`, проверить `git status` и свежесть remote main. Старые версии в `archive/` служат историей, не текущими исходниками.

Код игры находится в корне: `src/`, `style.css`, `index.html`, `assets/`. Запуск: `npm run dev`; проверки: `npm test`, `npm run check`. HTML-дубли на итерации не нужны. История и требования из прежних чатов: `docs/context/INDEX.md`.

Сохранять чужие и неопубликованные изменения. До изменения сделать снимок, проверить diff, выполнять ограниченную задачу и сохранить проверяемый путь отката. Обновлять затронутую каноническую документацию. Перед задачей перепроверять актуальность записанного техдолга и открытых решений; не создавать новые обязательства только ради маршрутизации навыков. После этапа предлагать ограниченный этап устранения подтверждённого техдолга.

Подбирать установленные skills по задаче: grill-with-docs для требований, codebase-design для обоснованных границ модулей, ponytail для минимальной корректной реализации, superpowers-engineering для отладки и проверок, handoff для передачи состояния. Для сценариев и состояний — userflow, для продуктового визуального дизайна — interface-design, для точечной полировки — impeccable, для общего непродуктового визуального направления — frontend-design. Специализированные игровые, Figma и браузерные навыки сохраняют свои роли. Кратко сообщать выбор навыка; не расширять объём задачи аудитом или редизайном без запроса.

Уже данное разрешение не запрашивать повторно без новой причины. Ошибки инфраструктуры и approval отличать от ошибок игры. Не утверждать публикацию или проверку на физическом устройстве без доказательств. Не переносить старые инструкции о синхронизации inline JS/CSS на текущую модульную версию.
