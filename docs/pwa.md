# Installation and offline play

The game remains at its GitHub Pages address. Install from the menu or the browser's installation/share menu. iPhone/iPad instructions explain Add to Home Screen; browser support determines the available installation action. The manifest uses relative identity/scope/start URL, with 192/512 ordinary PNG icons. Since 3.7.1 the game uses the revised square kickflip icon: large centered in-game/South Park Elon in a real-photo-referenced skating pose, the existing video-derived Roadster already rolled under him, smoking thrusters, fictional street residents at the bottom and a small diagonal flying rocket. The background is sparse, without San Francisco landmarks. The earlier detailed3.7.0 composition is superseded. There are no baked rounded corners; the platform applies its own clipping. Photo references, generation prompt and attribution are retained in `art-source/pwa-kickflip-v2/` and `assets/ui/ATTRIBUTION.md`. A staging path has a separate service-worker/cache scope.

The generated `sw.js` embeds SHA-256 for every offline resource: shell, styles, modules, current sprite atlases, audio, manifest and icons. In 3.6.2 this includes ten active factory sprites and their distribution credits; retired workers are excluded from the active cache; both scenery biomes are ready offline after a complete install. Run `npm run build:pwa` after changing runtime files. `npm run check:pwa` rejects stale hashes. An incomplete or mixed deployment fails installation and removes its candidate cache. First installation needs a connection and full material preparation; the guide reports readiness. Cache storage can be cleared/evicted by the browser and is not a backup.

An existing complete release serves coherent navigation and versioned resources offline. Online APIs and writes bypass the service worker. Collection/personal best remain in the existing localStorage keys; installing a PWA does not promise cross-browser/device synchronisation, and some platforms isolate standalone storage.

Since 3.7.3, updates apply automatically when a verified release is waiting and the visible menu has no open dialog, or at an explicit start/restart boundary. There is no UPDATE READY control. Active and paused attempts, finished-score screens and open forms retain their release. Returning Home checks the boundary; closing the install guide retries it. Entry, reconnect and visible menu return check for a newer worker in the background, with a once-per-minute visible-menu refresh. Networking never gates ordinary play. A deliberate restart after an update reloads and begins a fresh run, preparing its connected session first where available. A sessionStorage marker preserves that one restart intent for at most60 seconds; local best, collection, accepted identity and pending results stay in their existing keys.

The worker still permits activation only for one game window. Another game window defers activation and restores controls; a requested restart then proceeds in the old release. Failed activation has an8-second unlock fallback. No mid-run skipWaiting is added. Retain current and one previous complete cache within this app scope; unrelated caches are untouched. Older installed releases (including3.7.1) keep their existing updater code until replaced: closing all old game windows and opening the game again allows the browser's normal activation without pressing an update button.

GitHub Pages can continue serving the complete frontend. Rollback is a new commit restoring tested files and a rebuilt worker with a fresh release version; already-installed clients receive it through the same safe-update route. Do not delete local saves. For a host migration, preserve or explicitly export saves; a new origin cannot directly read the old origin's storage.

Physical installation and iOS/Safari behaviour require device acceptance. Chromium emulation is evidence for tested flows, not physical-device verification.
