# Independent PWA review: empty-level regression

The public 4.6.2 regression is real gameplay starvation, not an inferred cache problem. A fresh isolated browser installed the public service worker, reloaded offline, then used native touch events to charge, jump, rotate and release. After 40.258 active seconds and 24 flips the director still had zero waves. An automatic pause ended this baseline sample; `before-result.json` preserves the full state. No QA state mutation or director witness actions were used.

The candidate 4.6.3 was independently played for 180.067 active seconds from its installed offline cache. The input controller reacted to visible obstacle positions, performed voluntary tricks, released rotation, and used native touch events throughout. It completed 85 flips and 34 encounters while remaining alive; the largest interval between generated waves was 7.55 seconds. Thirteen models included factory vehicles and airborne qualitySkull/regulatorDrone, alongside optional rails and a spaced pair. Actual speed boosters, full streak speed and biome changes occurred naturally. `candidate-result.json` contains all samples and wave changes; `summary.json` is a compact extraction.

The baseline and candidate controllers deliberately differ: blind repeated flips are sufficient to expose starvation, but are not a fair survival test against functioning obstacles. Neither controller consumes `route.actions`. Do not interpret these runs as human enjoyment or a universal survival guarantee.

Code review confirms the root causes and bounded fixes: visibility formerly used base rather than effective camera speed; the fast branch disabled all ground candidates; voluntary flights postponed recovery of the spawning clock and coarse polling missed brief landings. The candidate tracks deterministic damped camera state, tests actual visibility during the combined simulation, admits validated single obstacles at high speed, reserves a safe optional rail fallback, and checks landing eligibility every simulation tick. Existing normal-speed preparation thresholds and the contiguous input window remain; fast single visibility is explicitly calibrated at 0.85/0.75 seconds. All historical replay folders are unchanged. `preserved-runtime.json` verifies that rotation physics, rail mechanics, camera rendering and audio controls match the published parent after version-string normalization.

Limits: desktop Chrome mobile emulation, not physical iPhone/Safari. The harness resumes through the actual UI if the game's long-frame guard pauses the run and records those events. No public scores were submitted. Candidate runtime was cached before a subsequent compatibility-list-only rebuild; the published release needs its own final check. Performance samples describe this desktop browser only.
