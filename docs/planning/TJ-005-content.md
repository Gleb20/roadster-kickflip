# TJ-005 — content package and desktop material studio

Confirmed 27 October 2026: game and authoring UI share a versioned, validated compatibility contract. Desktop web on Mac; inspect current materials, download originals, replace files, inspect dimensions/anchors and preview their actual assembly before shipping. Rarity is an explicit weighted-choice input after biome/safety eligibility, allowing ordinary repeats without pathological monotony. Biome owns scenery/ground/music only; HUD remains global. Music can be a full loop or synchronized stems; generation/preparation rules are part of this delivery.

Implementation boundary: one JSON source, generated immutable runtime module, content/resource SHA-256, engine/schema compatibility gates. Initial assets/geometry/music and probabilities stay equivalent: all current entries start with equal common rarity rather than inventing an unapproved balance. The weighted selector uses declared weights; draft rarity can be changed and previewed. Changed gameplay data must acquire a new frozen server ruleset before release; cosmetics can reuse a ruleset only when the gameplay digest matches its lock. This is a build failure, never a client-only claim of ranked compatibility.

Desktop studio: shipped package → browse/filter/select → download original or portable package → replace a material / edit draft metadata → validate → raw and production-rendered preview → export candidate. No live data mutation or public draft upload; publishing remains the verified coordinated release workflow until TJ-007 provides server authorization. Preserve draft on a failed import; transactional replacement only after complete validation/decode/hash checks. IndexedDB stores the local draft, with explicit restore and download. Preview runs isolated, without saves/ranking/PWA activation. A preview must never masquerade as a production result.

Acceptance: stable IDs and values round-trip; reject incompatible schema/ABI, duplicate IDs, missing/unknown references, unsupported profiles, traversal/remote resource URLs, malformed images/audio and missing bytes. Manifest hashes cover resources; gameplay hash binds dimensions, rarity, biome pools/cycle and reactions. Current two scenes retain production renderers/events and shared HUD. Material rules include image source pixel dimensions, atlas crop/layout constraints, world geometry and anchors. Audio metadata validation covers 128 BPM, 4/4, 32 bars / 60 sec, aligned stem duration; decoded media/silence/seam measurements inform readiness but hearing decides harmonic compatibility. Equal bitrate/sample rate alone does not prove a seamless transition.

Checks: package unit/round-trip/negative validation; deterministic weighted selection and no-repeat policy; exact old/new replay equivalence on complete natural attempts; existing game/server/frozen suites; desktop browser real download/upload/error/reload and production preview; mobile gameplay smoke; atomic incomplete PWA upgrade with old cache/data retained; published exact resource hashes. Bounded inverse restores parent in isolation; do not reset the original dirty checkout or remove data/verifiers.

Existing debt: TJ-D01 physical frame timing remains unmeasured; TJ-D02 old-tab activation boundary remains separate. Neither is automatically expanded here.


Desktop design: a quiet graphite workbench, warm yellow action accent inherited from the game, a compact library rail, wide assembly stage and fixed inspector. Actual materials and the resulting scene are the focal content. System fonts match Mac controls; monospaced metadata distinguishes source pixels/world geometry without adding game HUD options. Only desktop layout is designed; mobile gameplay is checked separately.

Existing scene adapters intentionally retain fixed resource paths and pixel layouts. This delivery edits current assets and known renderer profiles; it does not claim a universal scene compositor, arbitrary new choreography, cloud draft publication, role management or mobile authoring. Those belong to the subsequent biome/authorized-admin cards. All current rarities are common (weight 8); uncommon/rare weights are 3/1. The studio can preview and export different rarity values now; changing their ranked effect requires the coordinated ruleset release gate.
