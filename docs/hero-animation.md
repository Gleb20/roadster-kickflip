# Paper rider animation contract

`src/hero-rig.js` contains logical joint coordinates, a two-bone reach solver, declarative pose clips and pure arm/leg samplers. The renderer only paints the resulting limbs and hands. The origin is the riding soles, x right/y down. `HERO_RIG` names shoulders, hips, arm/leg lengths, sole offset and board reach. `HERO_APPEARANCE` supplies head cutout, clothing/shoe colours and emblem. A replacement cutout must be registered in the existing cutout adapter and keep the same logical head box; changing anatomy requires a matching rig. This is a development contract, not a player-facing character selector.

Use `sampleHeroArm(side, inputs, rig)` and `sampleHeroLeg(side, inputs, rig)` rather than adding another limb inside the painter. Arm layers run idle → wave/taunt → encounter interaction → board grab → seated brace/push → fall flail. Grab wins over waving; falling wins over grab. Head expressions, pointing hands and props stay specialised painters. Physics/collision still use the existing common silhouette; appearance changes must not silently change hitboxes.

`HERO_CLIPS` describes wave, brace and two flail poses. `sampleClip(clip,time,progress)` samples numeric, sinusoidal or keyframe channels without side effects; keyframes use ordered [progress,value] pairs with at least two distinct progress points. `solveTwoBone` clamps unreachable targets and keeps segment lengths; grab and seated legs use it. Standing legs retain the accepted authored knee shape while their sole anchors compensate for lean. No claim that every standing joint is a rigid skeleton.

`createHeroAnimation` / `advanceHeroAnimation` update gesture blends with simulation time. `characters.update(dt)` runs once per simulation tick; repeated rendering does not advance the animation. `characters.reset()` clears blends on a new attempt. Falling still uses the established fall timeline/contact markers, and its animation sampling does not change recovery or scoring.

The current paper limbs are already separately drawn, with reusable render surfaces and a bounded pose cache. Generating raster limb pieces now would add packing/loading and style-alignment work without a measured performance benefit. Keep this procedural rig, provide standard pivots for future replacements, and produce a photo/style-referenced asset package only when new artwork is requested. No Unity/Godot or runtime dependency is needed for this step; the browser/PWA baseline remains Canvas 2D with gradual type checking.

Verification targets: fixed reachable IK lengths, unreachable/zero-distance stability, photographed board/sole contacts through crouch/lean, layer priority, time-based blend invariance, fall contacts/recovery, paused input and normal jump/thrust/scoring. Rerun these when replacing a hero.
